# Conteneurs Atari ATR et ATX

Les neuf sources ATR et trois sources ATX C# actuelles définissent le périmètre. Les tailles, profils et géométries Atari communes sont séparés dans `Formats/Atari8Bit`. Les identifiants réutilisent le catalogue public MediaFileSystems ; aucune table concurrente d’identifiants n’est créée.

ATR valide la signature, les secteurs nominaux de 128/256/512 octets et le nombre de paragraphes 16 bits bas/haut. Ses variantes de récupération reproduisent les conditions précises du C# : image simple densité tronquée avec secteur d’amorçage cohérent, densité améliorée étiquetée 140 Kio avec VTOC/répertoire reconnus, longueur déclarée incluant l’en-tête et padding externe uniforme zéro ou 0x1a. Les pistes double densité dont les 384 octets finaux sont nuls utilisent la longueur utile conventionnelle.

Les trois premiers secteurs ATR restent de 128 octets. Les images simple densité tronquées sont complétées à 720 secteurs avec des zéros, comme dans la source. Les géométries standard physiques 18/26/28 secteurs par piste sont distinguées des vues logiques linéaires non standard ; capacité et nombre logique explicites sont conservés. L’écriture accepte les seuls profils 90/130/180 Kio, compare identifiant, nombre de blocs et capacité, puis valide chaque taille réelle de secteur. Elle n’ajoute pas une contrainte de taille nominale ou géométrie absente de MatchesGeometry C#.

ATX n’a pas de writer dans la source et aucun n’est inventé. Le lecteur valide offsets, limites des pistes et listes, nombres de pistes/secteurs/enregistrements. Le statut **0x10 signifie missing-data dans le C# actuel** : ces enregistrements sont ignorés avant de lire leur offset de données. Les autres statuts sont conservés dans DiagnosticCode et donnent IntegrityValid=false, y compris lorsqu’ils sont non nuls sans être missing-data. Les doublons préfèrent un statut nul, puis la position croissante ; une égalité conserve le premier enregistrement.

La position ATX sert à cette sélection, conformément au C# ; elle n’est pas exportée dans le modèle sectoriel courant. La source ne restitue pas de représentation de flux, de délais ou de zones faibles provenant d’extensions ATX : ce port ne revendique pas ces fonctionnalités supplémentaires. Les écritures ATR utilisent le producteur atomique existant, sans duplication d’une image complète pour le parcours par chemin, et RAII sur tous les chemins d’exception/annulation.
