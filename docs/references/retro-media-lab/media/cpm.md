# CP/M générique et Amstrad

Le port des 12 classes C# `FileSystems/Cpm` regroupe les dispositions dans `Layout.cpp`, les opérations de répertoire dans `Directory.cpp`, la reconstruction et le volume dans `Content.cpp`, les deux lecteurs dans `Reader.cpp`. Le header public `Cpm.h` expose les API générique/Amstrad, les ensembles CatalogFormatIds exacts, le sondage CPC et la spécification PCW. `CpmLayoutConstants.h` expose les constantes publiques CPC/PCW ; les constantes privées les aliasent sans duplication. Aucun writer n’existe dans ce dossier C#.

Le lecteur générique possède exactement huit formats : commodore.1541/.1571/.1581, epson.qx10.320/.396/.399/.400/.logo. Sa reconnaissance accepte les secteurs256/512/1024 et nécessite quatre entrées ordinaires plausibles, avec rejet des minuscules. Sa méthode Read conserve la règle source différente : elle ne refuse pas une taille sectorielle uniquement parce que CanRead la refuse. Le lecteur Amstrad possède amstrad.cpc, amstrad.pcw et cpcemu.dsk ; ses répertoires conservent les minuscules et nécessitent une fenêtre entièrement cohérente. Seul PCW autorise un répertoire complètement inutilisé.

Le format CPC privilégie la disposition déterminée par le premier numéro physique de secteur, puis recherche une fenêtre complète par pas de512 octets si nécessaire. Le sondage looksLikeCpcSystemDirectory reprend exactement la recherche source et ne dépend pas de l’identifiant de format. Pour Epson, les candidats sont examinés par pas de32 octets jusqu’à64Kio ; un score strictement supérieur remplace le candidat courant, l’égalité conserve le layout configuré. Cette recherche déplace uniquement le répertoire, sans déplacer l’origine d’allocation. La spécification PCW valide pistes, secteurs, codes de tailles, pistes réservées et blocs de répertoire ; les allocations deviennent larges au-delà de255 blocs.

L’aplatissement conserve la position de tous les blocs absents ou de taille différente. Les octets disponibles sont copiés sans décaler les secteurs suivants ; les allocations traversant une zone incomplète produisent des zéros dans le fichier. Une majorité strictement invalide d’allocations référencées rejette le fichier entier, sans produire les avertissements d’allocations du fichier rejeté. Un partage moitié valide/moitié invalide reste accepté et invalide ses métadonnées. Les allocations dupliquées sont signalées mais n’invalident pas seules le fichier, conformément au C#.

Les noms8.3 retirent les bits d’attribut et les espaces périphériques. Les extents sont regroupés par utilisateur et nom sans casse ; le premier groupe et sa première graphie sont conservés. Une table d’indices évite une recherche linéaire répétée sans changer l’ordre des groupes. Les extents sont triés de façon stable par numéro. Chaque extent conserve au plus RecordCount×128 octets ; les allocations nulles sont ignorées et la capacité libre soustrait l’union des allocations complètes utilisées et les blocs de répertoire.

Les deux lecteurs réutilisent exactement le même constructeur de volume, les modèles MFS existants et les diagnostics structurés traduits. Les commentaires techniques CP/M userN conservent leur clé de traduction et leur argument. Les bornes checked du C# deviennent des contrôles explicites avant multiplication/réservation ; aucun débordement signé C++ n’est utilisé. Les buffers sont possédés par RAII, les parcours longs acceptent l’annulation. Le branchement au registre global reste distinct de ces lecteurs complets.
