# Apple Lisa Office

Les 12 fichiers C# du dossier Apple/Lisa sont répartis dans cinq unités C++ : `Tags.cpp`, `VolumeHeader.cpp`, `Catalog.cpp`, `Content.cpp` et `Reader.cpp`. Le header public `Lisa.h` expose les versions/noms techniques, la lecture de catalogue et le lecteur de volume. Les fonctions d’en-tête/noms Latin1 réutilisent AppleRecognition déjà porté ; aucun algorithme n’est dupliqué. Les volumes et entrées emploient les contrats MFS existants. Aucun writer Lisa n’existe dans ce dossier C#, donc aucun writer supplémentaire n’est inventé.

Un tag doit avoir au moins12 octets. Les identifiants de fichier sont big-endian aux offsets4/5 ; les numéros de page aux offsets6/7 sont masqués sur11 bits. Le lecteur conserve les tags plus longs et ne déduit pas les valeurs des tags absents ou courts. Les pages MDDF sont triées de façon stable par numéro et la dernière est retenue ; les versions non reconnues ne sont pas rejetées artificiellement par Read. Le nom de volume provient du nom Pascal Latin1 limité à31 octets, tronqué au premier nul et débarrassé des espaces périphériques. Un nom blanc emploie Lisa.

Le catalogue tabulaire utilise des entrées de54 octets ; les dispositions hachée/B-tree utilisent64 octets à partir de0x50. Les versions autres que table suivent la branche des dispositions ultérieures, comme le C#. Les entrées utilisateur valides gardent le premier nom rencontré pour chaque identifiant. Les fichiers réservés sont exclus ; le catalogue absent reste un catalogue vide.

Les pages utilisateur sont regroupées et ordonnées par identifiant, puis par numéro de page et bloc logique. La reconstruction commence au premier numéro observé, sans inventer de pages manquantes avant celui-ci. Les lacunes suivantes insèrent des zéros de la taille de la première page ; les doublons sont signalés puis ignorés. Les tailles de pages différentes sont conservées. Les avertissements des fichiers sans nom de catalogue restent présents même si aucune entrée n’est affichée pour ces fichiers. L’espace libre compte les tags0/0x7fff, indépendamment du système de fichiers hôte.

Les données techniques du C# sont conservées, notamment `Fichier Lisa $NNNN` accompagné de sa clé et de son argument de traduction. Les six diagnostics sont structurés et traduits dans29 langues. Les noms techniques de versions table/hash/B-tree et inconnue-0xNNNN restent des métadonnées source, sans inventer un nouvel affichage. Tous les buffers et blocs partagés sont possédés par RAII ; les API C++ ajoutent une annulation. Les buffers sont limités à la représentation int32 du flux/tableau de référence pour éviter un dépassement C++.

Le registre global et ses adaptateurs document/volume restent un bloc distinct. Le filtre exact AppleLisaOffice (`applelisa.office`, sans casse) est déjà exécuté par canRead ; son CatalogFormatIds sera relié au registre complet.
