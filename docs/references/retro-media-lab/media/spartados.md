# Atari SpartaDOS 1.x et 2.x

Référence : les douze fichiers C# originaux `FileSystems/Atari/SpartaDos`, consultés en lecture seule. Le port utilise SectorImage, FileSystemVolume, FileSystemEntry et Timestamp existants, avec les primitives little-endian communes. Le codec de noms SpartaDOS retire seulement les espaces/NUL terminaux ; celui d’AtariDOS retire les espaces ASCII des deux côtés. Leur distinction a été vérifiée entre agents et aucun helper artificiel ne les fusionne.

Le secteur de démarrage est adressé en numéro physique 1, soit bloc logique 0. Il peut être court (128 octets) même pour une géométrie de 256 octets, dès lors que les 43 octets nécessaires sont présents. Le total de secteurs doit correspondre au nombre de blocs de l’image ; les plages root/bitmap, compte libre, code de taille et version 0x10/0x20 sont vérifiés. Le contenu du bitmap n’est pas parcouru dans la source : l’espace libre est celui annoncé par l’en-tête, et le port conserve ce comportement.

Les cartes de secteurs conservent leurs liens suivants/précédents, les références nulles pour les plages creuses, les limites et les cycles. La référence suivante est validée même lorsque le dernier pointeur utile a déjà été lu, conformément à l’ordre du C#. L’occupation additionne les secteurs de cartes et les références de données non nulles effectivement parcourues. Les secteurs de données plus courts que la géométrie provoquent une erreur ; les secteurs plus longs sont tronqués à la taille utile.

Les répertoires lisent leur propre longueur 24 bits dans leur premier secteur de données, puis les entrées de 23 octets. Les statuts inutilisés/supprimés sont ignorés, le statut nul arrête le parcours et l’ordre du répertoire est conservé. Un sous-répertoire utilise sa longueur réelle, pas la longueur de son entrée parente. Les ancêtres sont possédés par chaque parcours C++ : une exception libère le chemin automatiquement, et les répertoires réutilisés par des frères ne sont pas assimilés à un cycle.

Les noms sont ASCII avec remplacement des octets supérieurs à 127 par un point d’interrogation. Les dates/horaires nuls donnent une absence valide ; les champs impossibles produisent une absence et une métadonnée invalide, sans invalider les données. Les attributs de protection, masquage, archivage, sparse, versions et verrouillage sont conservés, ainsi que bootable, nativeTypeId, occupiedSize et dataValid.

Aucun writer n’existe dans les sources concernées. Les onze composants sont portés ; SpartaDosFileSystemReader reste partiel uniquement pour l’exposition de CatalogFormatIds et son raccordement au registre (neuf identifiants Atari déclarés dans le C#). CanRead, comme dans le C#, détecte l’en-tête sans filtrer l’identifiant de conteneur. Les buffers et chemins sont possédés et libérés par RAII sur sortie normale, erreur ou annulation.
