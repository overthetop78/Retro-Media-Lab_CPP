# Façades de conversion des fichiers sectoriels

Références C# consultées : services `IbmRawConversionService`, `MsxRawConversionService`, `BbcDfsConversionService`, `AcornAdfConversionService`, `AmigaAdfConversionService`, `AmstradDskConversionService`, `EpsonQx10ConversionService`, `UcsdImgConversionService`, `DecRx02ConversionService`, `D81ConversionService`, `AtariStConversionService`, `AtrConversionService`, `AppleSectorConversionService`, `AppleNibbleConversionService`, `MacintoshConversionService`, `LisaConversionService`, `CommodoreDosConversionService`, `CoherentConversionService` dans `Images/Conversion`.

Les façades sont regroupées dans `SectorFileConversion::Service`, avec une API publique par chemin et profil cible. Les anciennes surcharges prenant directement une image sectorielle correspondent aux writers déjà portés et au service général sur document opaque. Les familles restent séparées à la lecture, sans créer un second catalogue ou registre de codecs. La composition SCP possède explicitement les services capturés par les callbacks et expose les lecteurs ISO/Apple et les opérations Amiga/Commodore/RX02 nécessaires aux façades. Le helper statique de choix SCP/image du service général est également porté.

Règles conservées : sources IBM/MSX et BBC par leur lecteur typé ; source ADF conserve sa géométrie détectée, validation explicite du profil Amiga ; source UCSD TD0 ou brute relabellisée UCSD avant écriture. DSK/EDSK utilise le conteneur détaillé et le type demandé sans passer par l'adaptateur générique qui peut promouvoir une sortie standard en étendue. Epson conserve les métadonnées IMD et impose le profil lu ; les sources brutes reçoivent le profil explicite. Atari ST utilise la transformation existante, avec remplissage des secteurs manquants seulement pour une capture SCP. Les sorties Apple sectorielles utilisent les validations des writers ; Macintosh/Lisa conservent les métadonnées DiskCopy ; Lisa impose une source Lisa reconnue. NIB/WOZ utilise la signature SCP et la reconnaissance Apple automatique, avec les alias de catalogue du C#. Commodore DOS refuse un changement de géométrie et conserve la carte d'erreurs uniquement lorsque tous les secteurs possèdent un diagnostic. D81 et COHERENT utilisent le reconstructeur Commodore explicite, et non la sélection générique de candidats.

Les erreurs réutilisent les diagnostics traduits existants ; aucun nouveau catalogue à générer. Les conversions refusent un chemin de sortie identique au fichier source, comme la façade native SCP préexistante.

Validation du bloc assemblé : compilation Debug MediaEngine réussie, audit de 1493 fichiers C++ et 29 langues réussi. Contrôle ciblé des capacités de destination et alias Apple, copie IBM brute sans modifier la source, refus de réécriture du fichier source, conversion EDSK vers DSK avec conservation de l'adresse enregistrée et du statut du secteur, parcours Epson brut vers IMD et IMD vers IMD avec conservation du commentaire, du type de secteur et des données, annulation sans fichier de sortie. Aucun codec ni campagne de writers n'a été retesté. Les branches SCP réutilisent les reconstructeurs précédemment vérifiés ; elles n'ont pas fait l'objet d'une nouvelle campagne de médias dans ce bloc.

Le test comparait initialement le commentaire IMD avant l'ajout normal du préfixe de signature par le writer. L'attente a été corrigée pour comparer le commentaire réellement écrit dans la source au commentaire de la copie. Aucun changement de production n'a été nécessaire pour ce point. Le banc temporaire, son journal et les médias créés sont supprimés après réussite ; les médias du test sont également protégés par un nettoyage RAII sur exception. Le dépôt C# est resté en lecture seule.

Le portage global reste en cours : conversions optiques et de conteneurs de flux, inspection/détection et éléments MediaFileSystems restants.
