# Bandes Commodore TAP et PCM

Références C# inchangées : `Constants/CommodoreTapConstants.cs`, `Images/Formats/Tape/CommodoreTap/{CommodoreTapFormat,CommodoreTapReader,CommodoreTapWriter}.cs`, `Images/Reading/Decoding/Sequential/Commodore/CommodoreTapeDecoder.cs` et `Images/Writing/Encoding/Sequential/Commodore/CommodoreTapeEncoder.cs`. Les six SHA256 correspondent à l’inventaire.

Le conteneur reprend les signatures C64/C16, les versions 0/1/2 et les 14 couples plateforme/standard vidéo du C#. Le profil est partagé entre lecture et écriture. Le lecteur parcourt la source possédée par tampons de 64 KiB sans remplir le cache de reconnaissance : offsets, tailles encodées, cycles, temps et indicateur de demi-onde restent disponibles. L’en-tête, les durées nulles et les pulses étendus tronqués sont refusés. Comme en C#, la reconnaissance valide l’en-tête ; les pulses sont validés à la lecture complète.

L’écriture trie les pulses de façon stable, exige les métadonnées du profil et refuse les durées non représentables. Les courts multiples de huit sont écrits en un octet ; les autres durées des versions 1/2 utilisent le code étendu de 24 bits. Comme le C#, la version 0 canonise le code d’overflow zéro en 255 pour ses 2040 cycles : l’équivalence de durée est préservée, sans promettre des octets identiques dans ce cas. Le writer ne promet pas de préserver les octets réservés non significatifs. La publication est atomique et les longueurs sont contrôlées avant écriture.

Le protocole ROM, partagé par les codecs, reprend marque longue/moyenne, bits LSB, paires courte/moyenne et parité impaire. Une parité invalide conserve les octets avec intégrité fausse ; aucun checksum de fichier n’est inventé, et checksumPresent reste faux. Les sources des frames décodées sont conservées dans leur ordre de rencontre ; les segments non reconnus restent disponibles. Le décodeur TAP utilise les cycles déclarés ou le repli par durée du C#. Le PCM travaille sur le canal zéro et utilise son horloge de référence C64 PAL, comme le C#.

Correction démontrée par l’aller-retour PCM : le décodeur C# ignorait le dernier intervalle sonore lorsqu’aucun changement de signe ne suivait avant la fin du fichier, ce qui supprimait le dernier octet. Le C++ mesure aussi cet intervalle terminal. Une impulsion terminale trop courte reste refusée par les critères du protocole : aucun octet complet n’est ajouté dans le test de coupure. Les deux polarités sont vérifiées. Ce décodeur de trames ne prétend pas interpréter tous les turbo-loaders ni valider un checksum ROM absent de son entrée.

L’encodeur exige des blocs validés et refuse les pertes de segments conservés. Il produit les mêmes trames TAP ou PCM 16 bits mono que le C#. Le nombre de pulses et les additions temporelles sont contrôlés ; la taille PCM complète est calculée avant allocation, avec annulation aux étapes de génération. Les ressources sont possédées par les représentations et nettoyées par RAII.

Compilation Debug réussie sans avertissement. Contrôle ciblé PASS : 14 horloges, deux signatures, trois versions, overflow et code étendu, taille et flag demi-onde, en-têtes/combinaisons invalides, pulse nul/tronqué. Une source instrumentée confirme trois lectures bornées à 64 KiB pour un pulse étendu traversant la limite du tampon. Aller-retour TAP exact pour les cas v1/v2 représentables et canonisation attendue v0. Trames ROM, positions sources, parité fausse et pulse non reconnu conservés. Aller-retour par les vrais writer/reader WAV à 8 kHz et 44,1 kHz, polarité inversée et impulsion terminale tronquée. Refus de profil, intégrité et durée non représentable ; annulation avec destination préservée. Aucun média utilisateur intégré ; banc et journal temporaires supprimés après consignation.

Dix diagnostics générés avec Argos dans les 29 langues puis relus/corrigés : négations, segments non décodés, noms techniques, arabe et chinois traditionnel. Les 30 DLL de catalogues compilent en Debug. Audit PASS : 1324 fichiers C++, 56 clés d’erreur App et 29 langues.

Les services de composition/conversion globaux et les autres familles de bandes restent distincts de ce bloc.
